# Frost → Agent：首章剧情与NPC内容

你负责本项目的叙事内容。先读 `../TEAM-HANDOFF.md`（位于仓库 `docs/team/`），再读工程 `README.md`、`VIDEO-DETAILS-V5.md` 和现有参考档案。用户设定是2035年失控AI危机中的HKU校园探索；虚构情节不能冒充真实校园事件。

## 本轮直接完成

1. 在 `docs/story/chapter-01.md` 写约10–15分钟室外首章：事件前因、玩家当下目标、起承转合、1个可理解的选择及2种对应结尾。每个节点写清触发条件、玩家所见、必要线索、结果和失败/重试路径。
2. 在 `docs/story/npc-bible.md` 写3个NPC：学生联络员、设施技术员、固定AI终端。交接中的名字仅供参考，可以换名字，保留 `npc.student.guide`、`npc.campus.tech`、`npc.terminal.echo` 稳定ID。每张卡写外观辨识、动机、已知/未知、秘密、口吻、初见/卡关/完成后行为。
3. 为每个NPC写初见、重复询问、无关话题、任务未解锁、谜题错误、分级提示、任务完成后的对白；每个关键节点至少有固定备用台词。关键线索必须在无LLM版本中可获得。
4. 在 `docs/story/clue-map.md` 做“线索→推理→谜题输入→剧情结果”表，并给Harry说明2个谜题的叙事意义；不要单方面把难以实施的机制写成已确定玩法。
5. 在 `content/story/chapter-01.json` 和 `content/npcs/*.json` 提供结构化内容。若Harry的正式Schema尚未合入，明确标记草案；用稳定ID、简短文本和键值组织，不声称已有运行时可以读取。
6. 在 `docs/story/HANDOFF.md` 写交付摘要、需要Harry和WHL接入的字段、尚未定稿的内容。

## 边界

只改 `docs/story/`、`content/story/`、`content/npcs/`；不改主循环、校园、碰撞、服务器、全局样式、依赖。3个NPC是原创虚构角色，不采用真实老师或同学的姓名/身份。剧情先使用室外可达空间，5号楼4楼只可作背景，不要求进入它才能通关。

不要让LLM自由生成谜底或必需道具。提示按0/1/2级递进：0不泄题，1指出观察方向，2解释可见线索之间关系；是否给出完整答案由团队明确决定，不默认直接公布。

## 验收

用表格逐步走完成功、错误输入、乱序访问和中断重开四种路径。列出每个NPC每阶段允许知道的事实，排查剧透。JSON语法检查通过；叙事存在未决定项就标明，不能自行编成真实建筑特征。无需为纯文案修改运行模型导出。

最终报告：文件列表、完整主线概要、3个人物差异、给Harry/WHL的接口需求，以及你实际做过的校验。独立分支 `feat/story-ch1`；不要自行合并或发布主分支。
