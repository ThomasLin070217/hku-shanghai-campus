# Music upgrade — composer-skill round (owner direction, 2026-11-23)

Owner, verbatim:
> 音乐也有必要改进一下。你看一下我那个写音乐的 skill

Skill: `~/.claude/skills/vibe-compose-onezion` (v2.0.0) — score.json +
style.json → SMF → fluidsynth (`MuseScore_General.sf3`, MIT) → ffmpeg
highpass/lowpass/echo → loudnorm. Styles shipped: ambient-drone,
baroque-strings, lofi, music-box, organ-choir, piano, soviet-march,
string-quartet, strings-harp, symphony, viennese-waltz. Prerequisites are
installed on this machine (`fluidsynth`, `ffmpeg`, the 38 MB soundfont).

## What exists today

`scripts/audio/gen_music.py` (pure-stdlib synth) generates six 26.62 s,
22 050 Hz loops at 72 BPM / 8 bars in A minor → C major: `mus_safe`,
`mus_unease`, `mus_tension`, `mus_chase`, `mus_boss`, `mus_hope`.
`src/gameplay/storyAudio.ts` picks one by stage (`complete`→hope,
`chasing`→chase, `dark`→tension, `return_b5`→unease, else safe), crossfades
with `delivery.crossfadeMs` and aligns stems by a shared `epoch` so loops stay
phase-locked. SFX cues can duck the music bus; there is no transition stinger
for a solved puzzle, a powered building or a beam, and 8 bars of the same
arpeggio repeats noticeably.

## Target

One composed piece, arranged into intensity layers, plus event stingers.

1. **Style card** `styles/campus-2030/`: hybrid orchestral — sustained
   strings, piano arpeggio, low brass swells, synth pulse, restrained
   percussion; A minor with a C-major lift for `hope`. Tempo 72 BPM, 32 bars
   (about 106 s) so the loop is long enough not to read as a jingle. Reference
   policy: borrow technique, not notes (skill rule 2).
2. **Six layers of one score**: safe / unease / tension / chase / boss / hope
   share the harmonic grid. Each layer is a `score.json` + a per-layer style
   card (instrumentation and velocity only), so crossfades land on the same
   beat and never clash harmonically. Render 44.1 kHz WAV, loudnorm to a common
   target (about −18 LUFS short-term; music sits under SFX).
3. **Loop hygiene**: whole-bar loop points, no fade tail inside the loop; a
   seam check (first/last sample slope, click detector) and a per-stem
   loudness report.
4. **Stingers** (short, non-looping): `puzzle_solved` (rising fifth + chime),
   `building_online` (low impact + hum onset), `beam_strike` (choir/brass
   swell), `lion_alert` (brass hit). Wire them to campaign events through
   `StoryAudio.cue()` so they duck the music bus like existing SFX.
5. **Persistent progress layer**: after a building is powered, keep a quiet
   high-string/pad layer for the rest of the run (gain scaled by stage), so the
   campus audibly changes as puzzles are solved.

## Integration changes

- `src/gameplay/storyAudioAssets.ts`: replace the six `mus_*` URLs with the new
  WAVs (same ids keep the state machine unchanged), add the four stinger ids.
- `src/gameplay/storyAudio.ts`: add the progress layer to the music mixer
  (second loop key `music:progress`, level by `frame.stage`), and cue the
  stingers from the existing campaign event tap; keep the single shared
  `epoch`.
- `scripts/audio/gen_music.py`: keep as the fallback/legacy generator; the new
  score lives in the skill's workspace and is copied into `assets/audio/story/`
  with provenance + license notes (soundfont MIT notice).
- CI check `check-story-audio`: stem ids present, durations equal per layer,
  loudness within tolerance, seam check, no orphan files.

## Acceptance

- A/B the same 20 s walk between old and new stems; the owner picks.
- No click at any transition; layer changes stay on the beat (measure: the
  first transition in a browser run has no sample discontinuity above the
  threshold).
- All six layers share BPM/key/bar count; headroom under narration in the
  prologue.
- Licenses: score original, MuseScore_General MIT notice committed.

## Plan

### Task 1 — style card and score

Files (skill workspace, not the game tree): `styles/campus-2030/STYLE.md`,
`styles/campus-2030/style.json`, `scores/campus-theme/score.json`,
`styles/campus-2030/{safe,unease,tension,chase,boss,hope}.json`.

- Six-dimension style card (orchestration / rhythm / texture / harmony / tempo /
  mix) with `reference_policy` “borrow technique, not notes”.
- One 32-bar A-minor progression; `hope` lifts to C major in the last 8 bars.
  Roles: low strings, sustained strings, piano arpeggio, low brass, synth
  pulse, percussion; each layer card sets only instrumentation, velocity,
  register and mute/solo.
- Every layer is the same score, rendered six ways, so bar/beat alignment is
  exact. No layer may introduce a new tempo or key.

### Task 2 — render, loop and measure

Files: `scripts/audio/render-score.mjs` (new), `assets/audio/story/score/`
(new), `assets/audio/story/score/manifest.json`.

- Render each layer via the skill’s `compose.py` (fluidsynth +
  `MuseScore_General.sf3`), 44.1 kHz, loudnorm to −18 LUFS short-term,
  true peak ≤ −1 dB.
- Loop hygiene: whole-bar loop points, no fade tail inside the loop; measure
  the seam (sample discontinuity) and fail if above threshold.
- Manifest: per stem id, duration, bytes, sha256, LUFS, loop bars, source
  score hash, licence lines (soundfont MIT + score original).
- Keep `scripts/audio/gen_music.py` untouched as the legacy fallback.

### Task 3 — integration

Files: `src/gameplay/storyAudioAssets.ts`, `src/gameplay/storyAudio.ts`,
`src/gameplay/storyAudioAssets.ts` typings, `scripts/check-story-audio.ts`.

- Replace the six `mus_*` URLs with the new WAVs; ids unchanged, so the state
  machine and saves are unchanged.
- Add `music:progress` (a quiet high-string/pad layer) with its level driven
  by the campaign stage (off until the first PU is online, then a fixed low
  level, raised after the core). It joins the same `epoch` transport.
- Add stingers `puzzle_solved`, `building_online`, `beam_strike`,
  `lion_alert` to the cue table and fire them from the campaign event tap;
  they duck `music`/`ambient` like existing SFX.
- Crossfades: keep `delivery.crossfadeMs` but add a 0.12 s gain dip at the
  transition start only if a click is measured; do not restart the transport.
- If a stem is missing, keep the current fallback behaviour (silence for that
  id, no exception).

### Task 4 — gate and evidence

- Extend `check-story-audio` with: every layer id present, equal durations per
  layer, loudness within ±1 LU, seam check, manifest sha/bytes match, no
  orphan files, `music:progress` level mapping.
- Browser: load a save at each stage, capture the music state and one 10 s
  screen recording per transition; no click (measure via an AnalyserNode RMS
  discontinuity) and no narration duck regression in the prologue.
- A/B: old vs new stems on the same 20 s walk, both recordings attached for the
  owner’s listen.
