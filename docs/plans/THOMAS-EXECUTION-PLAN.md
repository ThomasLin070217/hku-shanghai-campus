# Thomas 开场：并行执行方案与可行性验证

日期：2026-11-18。源码基线 `f157e29`，Vite + TypeScript + Three.js v9 工程。

后续已进入开发，用户现改为自行派发外部 Agent。当前未完成快照、实际文件边界与四份可转发任务书以 [Agent 执行手册](../opening/agent-manual/00-START-HERE.md) 为准；本文的验证结论是此前基线/隔离原型，不代表当前半成品已联通。

结论：可以在现有工程完成，并适合采用“主集成 + 三个并行任务包”。先解决共享入口，再并行开发，最后统一接入与游玩验收。现有控制、物品、角色与道路足以作为基础，无需重写公共系统。Building 5/6 的可进入空间和剧情接线仍需新增；本报告不是已完成关卡的声明。

产品范围以 [已确认实施计划](THOMAS-OPENING-PLAN.md) 为准：全英文、2030、Building 4 门前巴士、Building 5 一楼进门右转、Building 6 简单取电脑、返回异常、慢速扫描/追逐机器人、打开电脑显示本地 AI 警报、Building 4 正门外交接。没有最低时长要求。

## 2. 需要前置处理的六个接入问题

| 问题 | 源码/验证事实 | 实施决策 |
| --- | --- | --- |
| 人类/RPC 分流 | `CampusGame.step()` 直接调用 `survey.interact/computer`；RPC 打开任务页只返回 `page_ready`，不打开 UI/暂停 | 单一内部 dispatch，由人类 F/C 与原 `/act` 共用；巡检模式回退现有 Survey |
| 多重 handler 与模态覆盖 | controller 的 Set 遍历所有 F/C 回调；experience 每帧控制电脑 modal，main 控制暂停卡 | 每个模式只挂一套输入路由，模态只有一个 owner；不能追加一层对话 DOM 就宣称接通 |
| 取电脑前无法存档 | `Inventory` 默认发电脑；`parseSave` 拒绝空背包，丢弃未知 opening 字段；不同实例 ID 的两台电脑会被接受 | 独立 opening 模式/版本封装，复用现有存储与背包；拾取和恢复都检查全局唯一电脑 |
| 入口封闭及高差 | B05/B06 为 `closed-exterior`；大阶梯上平台 Y=5.1，上部玻璃入口门底约 Y=9 | 门洞、模型空腔、地面承托必须同源；先用标注为估算的入口，不把两个高度混为一层 |
| 暂停不等于剧情声音停止 | `CampusAudio.setActive(false)` 后普通 ambient one-shot 仍可启动 | 沿用一个 AudioContext，给开场 cue 加显式生命周期、暂停/重试停止处理 |
| 全英文不止新对白 | 当前暂停卡、控制指南、背包、保存消息及地图仍有中文/CDS-1 | 对开场可见的公共界面注入英文 copy；不顺带重做开发者模型编辑界面 |

这些是可定位的接线工作，不是需要换引擎的阻碍。现有对外 `/act` 字段、权限、epoch 和控制协议继续保留。尤其 `interact` 目标仅允许字母/数字/下划线/连字符：使用 `opening-staff`，不要使用 `opening.staff`；剧情事件 ID 可独立保留命名空间。

## 4. G0：先冻结最小内部契约

这是准备新增的开场内部契约，不声称现有叙事 API 已存在。若队友交付到位，先做字段映射，复用其契约。

- `OpeningSnapshot`：阶段、revision、三个 flags、当前目标锚点、模态类型、机器人遭遇状态、待交接记录。任务状态只有 A 模块一份，UI/世界只读。
- `OpeningIntent`：读请柬确认、接受委托、拾取、确认警报、Retry、抵达锚点。状态层根据来自游戏本身的距离、朝向、遮挡与物品上下文校验，不信任调用者自报位置或完成标志。
- `OpeningResult`：是否接受、明确原因、文案 key、效果请求、最新快照。场景显隐和 UI 不直接改阶段。
- `OpeningSpatialLayout`：门洞、房间、承托面、出生/下车/Staff/电脑/返回异常/B04 交接锚点、巡逻节点、证据状态。模型、碰撞、地图使用同一份数据。
- 生命周期：模块提供 create/update/dispose 或等价接口；切模式、重建场景、重开和 pagehide 不重复挂监听或泄漏角色/声音。

输入/模态方案必须先验证：

1. 人类 F/C 与 RPC 进入同一内部操作；保持 `computer:'tasks'` 等原有枚举，开场时由阶段选择警报/应急页，不擅加 RPC `computer:'alert'`。
2. 首版复用 `explorer.openPanel('computer')` 的既有面板门禁，开场模式仅由一个 renderer 按 `opening.modal` 显示请柬/对话/电脑/Retry；旧巡检 renderer 只在巡检模式挂载。不扩展 `/act` 或 `panel` 枚举、不让两个 renderer 抢同一槽位。所有恢复移动/启用 AI 路径保持现有门禁，不能让 `Continue` 在对话仍打开时恢复移动。
3. 打开请柬、对话、电脑、失败界面均清输入、暂停、退出锁鼠标并撤销旧 epoch；关闭后不自动恢复控制。
4. 在 `CampusGame.step` 内操作导致暂停时，立即结束本帧，不能继续执行后面的 `body.step`。
5. 正常玩家通过英文按钮确认模态；移动仍由原物理处理。AI 实机验证依照页面人工授权规则；模态撤权后需重新授权，不为追求全自动测试放宽门禁。

G0 完成条件：最小 mock 能验证单一路由、模态挡住恢复/授权、旧巡检 fallback、同帧暂停零位移。未通过前，A/B/C 可以制作独立纯模块，不同时接 main。

该接线方法已有隔离原型证明：自动复制真实 `game.ts` 到临时测试 fixture，仅替换 dispatch 调用并增加暂停后的 early return，原 Action 校验不变。5 项断言通过，覆盖真人/RPC 同路由、同帧零位移与撤权、重复拾取唯一、原 `computer:'tasks'` 映射警报、Retry 保留电脑。该原型不包含正式剧情距离校验、DOM renderer 或完整存档实现。

## 5. 三个并行任务包的可执行步骤

### A：阶段、拾取、存档、Retry

1. 实现 `bus → invitation_read → travel_b5 → collect_laptop → return_b5 → incident → emergency_route → handoff`。内部阶段名可整理，三个对外 flags 不变。
2. 开场新游戏使用空背包；不改原物品 ID `macbook-air-13-silver`。唯一实例通过现有 slots/revision 和装备系统接入，不创建新的背包类。
3. 拾取先校验任务、交互目标和背包，再一次性写入物品/阶段；失败不隐藏电脑。重复 F、重复命令、重试均幂等。
4. 推荐 opening 使用 `hku.opening.v1`，旧 `hku.digital-survey.v1` 保留。复用存储所有权、设置、备份和安全位置校验；新解析器明确读取开场字段，不把 unknown 版本当合法旧档。
5. 自动保存 stamp 包含 opening revision；纯 flags 变化必须落盘。读档检查 flag/电脑一致性、实例唯一性、阶段合法性、检查点地面与碰撞。
6. 返回异常前生成遭遇安全检查点。被追上先暂停显示 Retry；重试回滚遭遇，不回滚取电脑、不重复发 `laptop_acquired`，不使用贴脸失败帧作为唯一恢复点。
7. B04 到达形成一次性待接收交接记录。下游未安装时也有明确终点；不发 `chapter_01_completed`。

交付验收：正确顺序/乱序/重复、拾取刷新、无电脑存档、两台电脑坏档、纯剧情保存、Retry、旧巡检档保护、多窗口冲突。

### B：实际通路、局部空间、扫描机器人

1. 先交 spatialLayout 初版，标明估算项；将下面已验证的外部路线作为候选，不把技术门洞坐标当实景结论。
2. 巴士固定在 Building 4 门前车道一侧；用减速音、车身轻晃和车门表现停车，不做可驾驶车辆或移动平台。三级小踏步/地板与视觉、承托共同生成，避开最终交接路线。
3. B05 只做一楼门厅与进门右转的最小晚宴区；B06 只做从入口到电脑的必要空间。模型 core、玻璃、浅景背板与碰撞都留同一个门洞；保留其他墙体。
4. 背景 NPC/家具布局提供正常/异常两态；返回时倒椅、遗落物与无人场地可辨认，仍保留逃生通路。
5. 机器人初版参数建议：低于玩家普通步速 2.6 m/s 的移动速度、有限扫描扇区、短暂发现确认、最后可见位置搜索和超时回巡。具体数值靠游玩调，不作为真实机器人参数。
6. 视野 = 距离 + 扇区 + 遮挡射线；只有可见时更新 lastSeen。丢视线后不得读取隐藏玩家位置重新导航；移动复用碰撞/固定步长，巡逻边必须通过物理校验。
7. 按用户选择：发现启动追逐，被追上才失败；失去目标可逃脱。暂停/电脑/失焦冻结机器人，不做伤害、武器或击杀。
8. 现有 authorKey 保持稳定。切分旧几何优先保持原语义键；新门框/空腔部件追加明确键，必要变更交旧→新迁移表。索引由生成器输出。

交付验收：所有路径双向通；窄门与同高室内衔接；玻璃不穿、其他墙不漏；机器人看不见墙后/背后目标、不穿墙、能甩掉、被抓可重试。

### C：英文 UI、人物、地图与声音

1. 基于现有像素风制作请柬、Staff 对话、拾取反馈、红屏/应急页、Retry。所有文本从 `en.ts` 取值，不塞进状态判定。
2. 请柬明确 `Student Ambassador`、`High Table Dinner`、`Building 5 · Ground Floor`、`Turn right after entering`。无已确认日期时不编具体活动日程。
3. Staff 2–3 个短段落，确认按钮 `I'll collect it`；在范围内交互、离开后能再谈，不重复接受任务。
4. 玩家打开电脑后直接显示警报；四条信息清晰，师生状态用 `may have been detained`，警报确认后突出 Building 4 目标。以剧情本地 AI 的检测结果呈现，不安装真实推理服务。
5. Staff 与 2–4 个学生使用已验证的角色模板/动画。正常/异常显隐取快照，不自己推进任务。
6. 地图目标与 3D 锚点同源，隐藏巡检记录点；一次只显示当前目标，不常驻大量箭头。Building 4/5/6 标签统一英文。
7. 英文范围覆盖开场可见的旧暂停卡、控制指南、背包/快捷栏、保存提示和 AI 状态；模型编辑与证据档案可继续中文。保持原按键 F/E/C/V 和物品系统。
8. 音效复用一个 CampusAudio；先用已有音效/本地合成短 cue 建立可读反馈，素材授权清楚后替换。bus/door/disturbance/scanner 等 cue 在暂停、Retry、切模式与 dispose 显式停播/清理。

交付验收：1440×900 / 1366×768；英文无溢出；对话焦点/Tab/Esc 正确；不与暂停卡重叠；空手按 C 不生成电脑；静音仍能理解扫描与异常。

## 6. 已通过的空间技术原型

全部使用当前 `CharacterPhysics`、1/120 s 固定步长、2.6 m/s 行走，不通过浏览器瞬移模拟通关。初始化测试位置是离线 fixture，不是游戏中的运行时位置修改。

| 验证 | 实测结果 | 能证明什么 |
| --- | --- | --- |
| B04 前场 → B05 外 | 59.68 s，通过 | 候选外部路线可行 |
| B05 外 → B04 正门外 | 62.94 s，通过 | 回程与交接区可达 |
| B05 前场 → 礼堂阶梯底 → 5.1 m 平台 | 39.27 s，通过 | 必须绕至小踏步中央路线，不能侧穿高差 |
| B05 临时 2.4 m 门洞 → 右转 → 返回 | 通过 | 当前物理可支持最小一楼空间 |
| B06 阶梯 → 临时同高门洞/室内 → 返回 | 通过 | 同高承托/开口方案可行 |
| 巴士三级 18 cm 台阶上下 | 通过 | 无需新控制器即可下车 |

候选 `(x,z)` 路线：

- B04→B05：`(58,33.5) → (24,33.5) → (24,-48) → (58,-48) → (58,-53.8)`。
- B05→B04：反向返回前场后到 `(58,25)`，模型 Y≈0.08。
- B05→B06：`(58,-48) → (24,-48) → (18,-48) → (18,-26) → (4,-26) → (4,-52.2)`，末端模型 Y=5.1。

已复现的不可走捷径：`z=-50.5` 穿连接区会撞柱；从阶梯侧沿横穿会遇到 `terrain-rise`。保持结构，走合法通路。

原型仅在隔离 Navigation 实例中分割 `closed-exterior`，六处门旁/背墙仍阻挡，两个门洞开放；不删除整栋边界。**B06 Y=5.1 的技术门洞不等于已确认的真实入口。** 当前模型上部玻璃门底约 Y=9，不能误接至大阶梯平台。实景不足时选明示估算的简化入口与局部空间，等补拍再校准。

机器人另有 7 项隔离原型断言：视锥内无遮挡可见、背后不可见、B05 墙体遮挡、发现后追逐而不立即失败、暂停冻结、隐藏目标不更新 lastSeen 且搜索后回巡、近距离捕获才失败。移动使用现有 CharacterPhysics，约 1.3 m/s，记录 65 帧 trace。此为行为可行性证明；完整巡逻图、动态倒椅/门洞后的遮挡与实机难度仍需集成验收。
