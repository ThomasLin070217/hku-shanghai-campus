# Opening prologue — plan (2026-11-23)

## Goal

A short, skippable, in-engine cinematic plays before the player first takes
control. It explains the world in 30 seconds — HKU Shanghai CDS campus in 2030,
built as one supercomputer, sealed by an intruder, the students gone, the player
the only Student Ambassador still free — then hands off to the existing bus
wake-up without a cut.

Owner request (verbatim): "然后一开始是不是可以做个简单的动画，交代一下 CDS
校园和世界的背景。…配音可以用我的 11labs api / 然后游戏里主人公的配音也可以用我那个"

## Canon

Source: `doc/11-barrier-2030-design.md`, `doc/12-design-state-2026-11-21.md`,
`doc/meetings/2026-11-18-team-kickoff-notes.md` in the docs repo.

- 2030, HKU Shanghai CDS campus. The campus is a supercomputer: four towers
  (PU 01–04) around a central auditorium core.
- An external AI got in during the opening; a barrier seals the campus; the
  guardian lion is infected (repair it, do not kill it); students are detained
  at the sports hall.
- The player is the only Student Ambassador still free, with a MacBook that
  still has root.
- Route unchanged: bus → B5 High Table Dinner → MacBook errand → B4 keyboard
  wall → lawn lion → sports hall rescue → lights show.

No new canon is introduced. The prologue only states what the campaign already
assumes.

## Visual design

In-engine, no video asset. The camera flies over the existing voxel campus with
letterbox bars, a bottom subtitle, and one title card.

- Camera: the existing exploration perspective camera, driven by five shots
  derived from the campus bounding box at runtime. No runtime model edits.
- Shot boundaries are the clip starts above, so speech and picture change
  together.
- Shots (all positions relative to the campus box centre `c` and span `s =
  max(size.x, size.z, 60)`):
  - A `0.00–8.89` — high south-east aerial, slow drift toward the core.
  - B `8.89–18.06` — descend and swing west across the four towers, red
    emergency wash visible.
  - C `18.06–23.05` — low glide toward the entrance/bus spur.
  - D `23.05–25.91` — close on the central core during the player line.
  - E `25.91–30.46` — rise and settle onto the player's spawn camera pose,
    so stopping the prologue leaves the first-person view already correct.
- Easing: smoothstep between shots; a small continuous drift so no shot is
  frozen. FOV 52 during the prologue, restored on exit.
- Sound: the narration through `CampusAudio.playVoice(buffer, {gain: 0.9})`, no
  position, SFX group. The existing campus ambience is ducked to 0.35 while the
  prologue plays and restored after.
- Overlay DOM (`#prologue`):
  - start gate with the title `BARRIER 2030`, one line "A CDS campus story",
    and a `BEGIN` button. This click is the audio unlock; nothing is generated
    before it.
  - letterbox bars top and bottom; subtitle at the bottom of the frame, max
    two lines, 18 px at phone width;
  - `Skip` in the top right (tap target 48 px), plus `Esc`/`Enter` on desktop;
  - end title card 1.2 s after line 5: `RESTORE THE TOWERS · FREE THE STUDENTS`
    over black, then fade to the pause screen.
- The pause card is hidden with `body.prologue-active` while the cinematic runs;
  it returns (game still paused) when the prologue ends or is skipped.

## Trigger

Plays when all hold: opening mode, story stage is `bus`, no `?checkpoint=`, no
`?intro=0`. `?intro=1` forces it, including after a save. Once per session:
`sessionStorage['hku.campus.prologue.v1']`. It does not modify the save.

The browser gate uses `?intro=1` and a debug API to seek; production players see
it once per session.

## Tasks

### Task 1 — narration assets and timeline data

Already generated: 5 mp3s + `clips.json` (29.07 s of audio, 30.46 s timeline).

Create `src/opening/prologueTimeline.ts`:

```ts
export const PROLOGUE_GAP = 0.35;
export interface PrologueClip {id: string; speaker: 'narrator' | 'player'; text: string; duration: number; file: string; voiceId: string}
export interface PrologueLine extends PrologueClip {start: number; end: number}
export function prologueTimeline(clips: PrologueClip[], gap = PROLOGUE_GAP): {lines: PrologueLine[]; total: number; audioTotal: number}
```

Rules: order preserved; first start 0; each next start = previous end + gap;
`total` = last end; `audioTotal` = sum of durations; a non-finite or negative
duration throws `Error('prologue clip <id> has no valid duration')`.

Create `src/opening/prologueVoice.ts` that imports `clips.json`, exposes
`PROLOGUE_CLIPS: PrologueClip[]`, `PROLOGUE_LINES`, `PROLOGUE_TOTAL`, and a
static `PROLOGUE_URLS: Record<string, URL>` built with
`new URL('../../assets/audio/prologue/prologue-1.mp3', import.meta.url)` for
each of the five files (Vite cannot analyse a template path).

Create `scripts/check-prologue.ts` and wire `check:prologue`. Assertions:

1. `prologueTimeline` math: starts from the fixture durations, gaps, total,
   single clip, empty list, and a negative duration throws.
2. every line in `content/voice/prologue.json` has a clip with the same id and
   text, a positive duration, and a file that exists;
3. `clips.json.total` equals the sum of durations within 0.01 s, and the total
   is ≤ 45 s;
4. each speaker maps to a voice in `voices`, the player line uses a different
   voice from the narrator, and every clip id has a URL in `prologueVoice.ts`.

Task 2 extends the same check with the mount and stylesheet asserts, because
those files do not exist at Task 1.

Run it before writing the browser-facing code; run
`node scripts/generate-prologue-voice.mjs --check` too.

### Task 2 — prologue module

Create `src/opening/prologue.ts` exporting:

```ts
export interface PrologueOptions {
  viewer: {scene: T.Scene; camera: T.PerspectiveCamera; beforeRender: {add(fn: (dt: number) => void): void}};
  explorer: {camera: T.PerspectiveCamera; pause(reason: string): void; resume(reason: string): void; game: {paused: boolean}};
  audio: CampusAudio;
  root: () => T.Object3D;
  clock?: () => number;
}
export function createPrologue(options: PrologueOptions): {
  readonly active: boolean;
  play(): Promise<void>;
  stop(): void;
  debug: {seek(seconds: number): void; state(): {t: number; line: number; shot: number}};
};
```

Binding behaviour:

- Mount the overlay lazily on `play()`, not at import. `play()` first awaits
  `audio.start()` (inside the click), then decodes the five bundled mp3s with
  `audio.context.decodeAudioData`, then starts the clock.
- The clock is the audio context time when available, else
  `performance.now()/1000`; `debug.seek` offsets it and is only reachable in
  DEV/review through `__CAMPUS.prologue`.
- Subtitles are set with `textContent`; a line's subtitle shows from its start
  to start+duration, with a 0.12 s fade. The player line uses a distinct class.
- Camera override runs in `viewer.beforeRender` and must be added after the
  explorer's own update; it sets position/quaternion directly and restores the
  previous FOV on stop.
- `explorer.pause('prologue')` on start; on stop/skip leave the game paused and
  remove `body.prologue-active` so the pause card returns. Do not call
  `explorer.reset()`.
- Skip on `Escape`, `Enter`, or the Skip button; skip stops all voice handles
  (`stop()` on each `playVoice` return) and resolves the `play()` promise.
- `stop()` is idempotent and safe before `play()` (no overlay, no listeners).
- `dispose()` removes listeners, overlay, RAF/callback and restores audio gain.

Create `src/opening/prologue.css` and import it from the module. Rules:
letterbox `position:fixed`, `z-index` above the HUD but below the pause card in
normal state; `body.prologue-active #pause-panel{display:none!important}`;
subtitle `max-width:min(760px, 88vw)`, 18 px / 1.5 at ≤700 px; safe-area insets;
`prefers-reduced-motion` removes drift (camera cuts still happen, easing becomes
linear); Skip 48×48 minimum.

Mount in `src/main.ts`, after the atmosphere block and before the final
`mode(true)`-dependent UI is used for play:

```ts
const prologue = openingMode
  ? createPrologue({viewer, explorer, audio: experience.audio, root: () => asset.root})
  : undefined;
```

Then start it only if `story.stage === 'bus'`, no checkpoint, and
`params.get('intro') !== '0'`, or `params.get('intro') === '1'` forces it.
Guard `sessionStorage` in a try/catch. Expose it in `__CAMPUS` for DEV/review.

Extend `scripts/check-prologue.ts` with: `src/main.ts` calls `createPrologue`
and exposes `prologue` on `__CAMPUS`; `src/opening/prologue.css` contains
`env(safe-area-inset` and a `body.prologue-active` rule that hides the pause
panel; `src/opening/prologue.ts` registers its camera callback on
`beforeRender` and calls `explorer.pause('prologue')`.

### Task 3 — browser gate

Create `scripts/check-prologue.py` (Playwright, local, not CI) against a frozen
review build served with `?experience=opening&intro=1`:

1. `#prologue` visible; `#pause-panel` not visible; `body.prologue-active`.
2. Click `BEGIN`; assert `__CAMPUS.prologue.active === true` and that the

3. Seek to each line start via `__CAMPUS.prologue.debug.seek`; assert the

   moved > 0.05.

6. Reload without `intro=1`; assert the prologue does not appear.
7. Screenshot `evidence/prologue-<sha>.png` at the shot-B seek point.

## Acceptance

- `npm run check:prologue`, `npm run check:mobile`, `npm run typecheck`,
  `npm run check:opening`, `npm run check:campaign` pass.
- Browser gate passes with the screenshot; subtitles match the spoken lines;
  skip returns to a paused, playable game.
- Desktop and phone both: no layout shift at the handoff, controls work
  immediately after Skip.
- Owner listens and confirms the narrator and protagonist voices, or names the
  replacement voice IDs.

## Risks

- WebAudio needs a gesture; the BEGIN gate exists for that reason and must not
  be bypassed.
- The camera override must come after the explorer's update; if it is added
  first, the player's pose wins and the flyover is invisible.
- The prologue must not run on a checkpoint build — every browser gate starts
  at `?checkpoint=b4`.
- Voice clips are committed binaries (~460 KB total); regeneration is
  deterministic in text but not in prosody, so clips are not re-generated by
  checks.
