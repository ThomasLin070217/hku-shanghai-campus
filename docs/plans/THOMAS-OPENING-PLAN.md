# Thomas 开场关卡实施计划

日期：2026-11-18。审查基线：`f157e29`，项目版本 `9.0.0`。

本文件是实施计划，尚未实现或试玩新关卡。流程为校园巴士 → B05 → B06 取电脑 → B05 异常与机器人 → B04 交接。采用用户本轮与最新飞书参考中的 2030 年设定。10–11 分钟仅用于控制开发范围，不是固定时长或最低游玩时长，不为凑时长新增内容。

后续已完成三 agent 并行可行性审查、现有全量检查、浏览器启动与隔离技术原型。具体任务包、共享文件所有权、依赖门槛与实测证据见 [并行执行方案](THOMAS-EXECUTION-PLAN.md)；下文“审查结论”保留最初审查范围，最新验证以执行方案为准。

### 用户补充决定（2026-11-18）

- 游戏面向玩家的名称统一为 `Building 4`、`Building 5`、`Building 6`，不再使用 CDS-1；源码稳定编号 B04/B05/B06 和历史证据名称保留。
- 巴士剧情停在 Building 4 门口；具体安全落点和车门方向由场景与碰撞核对。
- 晚宴在 Building 5 一楼，进门后右转。该室内路线与房间需要补拍，不能继续仅做楼外接待。
- Staff 为现场工作人员或教授，知道玩家是 Student Ambassador，委托取晚宴展示电脑。具体造型不影响实现，可先用工作人员模板。
- Building 6 直接到指定地点拿电脑，不加谜题、找钥匙或复杂楼层流程。
- 通过混乱声音、倒地椅子和无人场地让玩家察觉事件；前半段温暖自然，之后逐渐变得诡异，避免血腥和持续惊吓。
- 机器人慢速巡逻，红眼扫描，不预知玩家位置；玩家不能攻击机器人，只能躲避和逃跑。用户已选择追逐规则：扫描确认发现后慢速追逐，被追上才失败；脱离视线后搜索最后可见位置，再恢复巡逻。
- 玩家打开电脑后直接显示警报，不强制自动弹窗。电脑中有本地部署的 AI，因接入校园网络感知攻击并进入应急模式。剧情本地 AI 与开发工具/玩家操控 AI 分开；技术默认仍可无模型服务确定性通关，不额外安装真实推理服务。
- 本轮所有新增玩家可见的对话、请柬、任务、提示、失败界面和电脑内容统一英文；开发文档可保留中文。

最终确认：机器人被追上才触发失败，重试回到本次遭遇前的安全检查点，保留已取得电脑与此前进度；Thomas 段止于 Building 4 正门外的交接点，Harry 接管进入后的内容。玩法选择已明确，剩余为实景核对与下游事件名的技术对齐，不再将这两项列为待定设计。

## 5. 按依赖推进的实施批次

### P0：冻结基线与最小接入方案

- 运行 `npm ci`、`npm run play`，记录新游戏/读档/巡检现状与检查结果。
- 保存校园俯视、R009、B05、B06、B04 入口、背包和电脑的固定相机/画幅基线。现无巴士/对话/红屏，标注“新增界面”，不伪造修改前截图。
- 再查队友最新源码、任务契约及 B04 接入点；列出缺失能力和必要的最小公共改动。
- 用现有物理逐段走通候选路线，再登记锚点。先解决 B05 一楼入口/右转空间及 B06 开口和标高，避免室内做好后无法到达。

通过标准：所有互动位置可达，任务与 UI 的权威边界明确，现有巡检入口与旧档有保护方案。

### P1：完整流程原型，先确保可玩

- 新增开场场景模式与确定性剧情状态，用现有 HUD/面板呈现最小交互。
- 巴士用有限内饰和车门模型；短暂减速声、轻微车身晃动与窗外运动表现抵达。避免先做真实行驶载具和移动平台系统。
- 玩家在车内合法承托面出生；读请柬后解锁下车，车门只在停车完成后打开。通过现有物理走过车内通道和台阶下车，台阶满足现有跨步限制。过渡镜头不写玩家世界坐标。
- B05 一楼进门右转处做最小晚宴/接待空间，放 Staff 和 2–4 名背景学生；Staff 认出 Student Ambassador 并提出取展示电脑的委托，确认后更新 Building 6 目标。
- B06 做直接可达的简化取电脑区域，通过距离、朝向、无遮挡和前置任务检查拾取电脑，不添加其他解锁流程。
- 将唯一电脑实例放入既有背包/快捷栏；事务成功后才隐藏世界电脑、设置旗标及保存。重复交互、满包、刷新均不能吞物品或复制电脑。
- 带电脑返回 B05 后，切到无人晚宴区、倒地椅子与异常声景，启动慢速红眼扫描机器人遭遇；打开电脑直接出现本地 AI 警报，确认后变为应急模式。
- 到 B04 交接锚点时发出进入事件并完成 Thomas 段；下一关未安装时显示明确的交接终点，不伪装成完整第一章通关。

通过标准：无网络、无 LLM，从新游戏完整走到 B04；乱序互动不能提前推进，所有模态关闭后无粘键。

### P2：存档与恢复，同一批完成防软锁

- 在现有存档机制中增加可区分的开场模式与版本；保留旧巡检档及其读取路径，不静默把巡检进度换算成故事进度。
- 支持未拿电脑存档；阶段与物品必须一致。未知版本保护/备份，损坏状态给出明确恢复反馈。
- 保存剧情阶段、三个交接 flags、唯一道具实例、已完成的一次性事件及安全检查点；UI 可见性、NPC 显隐和灯光从状态重新派生。
- 巴士开门中、对话中、拾取瞬间、警报中、威胁中读档：恢复到对应安全边界；不让玩家复活在车外空中、关闭的门内或机器人身上。
- 被机器人追上后可重试遭遇，不重跑取电脑段；检查点回滚同时恢复机器人、玩家和剧情状态，保持唯一电脑实例。扫描发现只进入追逐，不直接失败；避免自动存档把玩家锁在必败位置。
- 老世界版本的危险坐标沿用现有安全落点校验，但按剧情阶段选择已解锁检查点，避免回到已无法再出发的巴士。
- 重新开始必须重置本模式的 NPC、电脑、事件和场景状态，并保持设置与 AI 权限规则一致。

通过标准：在每个关键阶段刷新后仍能完成开场，重复事件只生效一次。

### P3：局部 UI、NPC 与入侵演出

- 本轮新增的所有玩家可见内容统一英文，包括任务、地图楼名、对白、请柬、警报、交互提示与失败/重试；不使用 CDS-1 作为玩家目标名称，不加入双语切换系统。
- 请柬：沿用校园绿色、暖白纸面及像素风边界，突出 `High Table Dinner`、`Student Ambassador`、`Building 5 · Ground Floor`；日期/时刻无资料时不填具体值，不假装真实活动信息。阅读后可重看。
- HUD：左上只保留一个当前目标与简短地点；任务详情折叠。地图目标取同一锚点源，临近转弯才显示短提示，不常驻满屏箭头。
- Staff：复用 `createCharacter` 外观与待机。英文对白草案："You're one of our Student Ambassadors, right? Could you collect the MacBook from Building 6? We need it for tonight's presentation. Bring it back here when you've got it." 玩家确认后才接受任务，中途退出允许再谈。
- 对话/请柬/电脑统一复用暂停、清键、释放 Pointer Lock 和焦点恢复机制；开窗时撤销 AI 授权，关闭后需明确继续，不自动前进或重新授权。
- 拾取反馈：一次短提示与快捷栏强调；第一/第三人称只走已有持物插槽，不再附加第二台手持模型。无电脑时按 C 给当前阶段的合理反馈。
- 警报：玩家打开电脑后直接进入深色红色警报屏，不自动夺取操作。信息来自电脑本地 AI 对校园网络攻击的检测：机器人受控、屏障隔断外联、师生可能被拘禁、Building 4 应急设施可用。英文文本区分网络可检测事实与推断，不把“师生可能被拘禁”说成已确认。
- 警报后切应急辅助页，突出 B04 楼名、目标图标和路线；保留关闭、重看与地图入口。按 C 默认进入与当前阶段对应的页面，不只靠 toast 传达关键情报。
- 无人晚宴区在玩家离开 B05 后、返回可见前完成状态切换；加入混乱声音、倒地椅子和少量遗落物，结合先前 NPC/交谈声消失形成明显变化，不在眼前凭空删人。倒地椅子不堵死唯一逃生通路。
- 一台机器人采用开场专用有限状态：慢速巡逻 → 红眼扫描/疑似目标 → 确认发现 → 慢速追逐。追上玩家则失败重试；失去视线则前往最后可见位置搜索，搜索结束仍未发现玩家就恢复巡逻。玩家不能攻击或击毁机器人，能够躲避与逃跑；不做武器、血量或伤害系统。
- 扫描有可读的方向/范围表现；发现判定依据视野范围、距离和视线遮挡。机器人不知道墙后或视野外的玩家位置，不把玩家实时坐标作为持续追踪的全知目标；需要追逐时只使用可见目标或最后可见位置。
- 机器人不穿墙、不瞬移；电脑、背包、对话及失焦时冻结遭遇。失败界面提供清晰英文原因和 Retry。静音也能靠红眼扫描、动作和文字理解威胁。

通过标准：玩家不用开发者解释能理解身份、委托、拾取结果与 B04 目标；没有模态遮挡、失焦误走或重复红屏。

### P4：路线内建模与实景修正

- 优先修复阻路碰撞、入口开口、错层台阶和玻璃后实心遮挡，再补沿途铺装、路缘、树、花坛、灌木与标牌。
- 复用当前 `glazing.ts` 的透明玻璃/框架/浅景深结构；旧依据文档提到不透明玻璃，不代表当前源码仍如此。只修现场核实的问题，不整栋降低透明度或删除全部外墙碰撞。
- B06 入口只开放剧情需要的通道；其余建筑边界继续有效。取电脑房间使用清楚的“2030 剧情空间”资产元数据，公共区域依据和虚构装饰分开记录。
- 地面/台阶从共同参数生成视觉与碰撞，沿用 `groundLayout.ts` 和现有导航结构。装饰绿叶不逐叶阻挡，树干、硬花坛与结构柱按实际占地处理。
- 保留已有 `authorKey`、`authorParts`、`sceneId`；新增部件 append-only，生成场景索引，不手改 catalog。需要历史迁移时提供旧→新表。
- 只修改开场可见/可走范围，不顺带重做其他楼层、全校景观或后续关卡资产。

通过标准：模型和碰撞一致、同机位对照有依据、未确认项明确；未收到新素材也有可玩的保守版本。

### P5：完整游玩、回归与交付

- 从清空的开场档按用户要求的十步实际游玩，再补走到 B04 入口完成交接。
- 记录阶段时间、路径、卡点、FPS/帧耗时与关键事件，区分主动游玩和暂停时长。
- 截图第一轮集中检查桌面 1440×900、1366×768 的五处关键界面及路线，再集中修复，复核一次；功能缺陷另外修复回归。
- 提交实际操作录屏与检查记录，不用测试里直接设置剧情阶段冒充通关。

## 6. 触发条件与事件约定

三个 snake_case 名称已在用户要求及飞书表中出现，作为对外稳定事实。其他名称仅为本地提案，正式实现前检查队友契约并写映射表。

| 节点 | 前置/触发 | 写入与反馈 |
| --- | --- | --- |
| 请柬已读 | 车内打开并确认请柬 | 对外 `invitation_read`；允许停车后下车 |
| 离开巴士 | 停车、车门开启、跨过出口区域 | 本地提案 `opening.bus_exited`；目标 B05 |
| Staff 委托 | 到达 Staff、合法交互、确认对话选项 | 本地提案 `opening.laptop_requested`；目标 B06 |
| 拿到电脑 | 委托已接受、电脑在范围内且无遮挡、背包写入成功 | 对外 `laptop_acquired`；隐藏世界道具、目标返回 B05 |
| 返回异常 | 有电脑且委托阶段正确，进入 B05 返回触发区 | 对外 `campus_alert_triggered`；切换场地、激活机器人与电脑警报待阅读状态 |
| 读完警报 | 打开已装备电脑、确认警报内容 | 本地提案 `opening.alert_acknowledged`；解锁 B04 应急目标 |
| B04 交接 | 三个 flags 成立、警报已确认、进入 Building 4 正门外交接范围 | 本地提案 `opening.building4_reached`；对接后续任务的实际进入事件，进入后的内容归 Harry |

B04 的最终事件名是现阶段唯一需要与下游契约对齐的命名项，不把提案声称为既有事件。交接数据至少包含版本、来源阶段、目标锚点、三个 flags、电脑实例 ID 和已投递事件 ID；读取接口返回同一权威快照。

事件必须验证前置阶段、目标与距离，记录去重 ID。拾取/发 flags/存档形成一致操作；刷新失败可重试。恢复存档应能重建世界状态，下游未挂载时保留交接待接收状态，再次挂载只消费一次。

本轮绝不发出 `supercomputer_online`、`ai_core_power_cut`、`students_rescued` 或 `chapter_01_completed`。这些表示后续真正完成的剧情，不能用来代表 Thomas 段结束。

## 9. 模型协作方式与最终产物

Codex 负责集成、源代码核对、运行和验收。若调用用户允许的其他工具，按独立文件/分支拆工：Claude Code 可复核状态机、存档和碰撞边界；WorkBuddy 可评审五处开场 UI 与游玩卡点；DeepSeek Flash、MiniMax 或 Qwen 可起草英文短对白与测试边界清单。每项任务给定输入、禁止编辑范围和验收结果，不让多个工具同时改共享入口。

模型输出是开发辅助，剧情运行保持离线确定性；不把外部模型接成推进任务的必需条件。仅在实际可用且已授权的连接中调度，不虚称已调用某模型。当前计划由本地审查和飞书参考核对形成，尚未调度这些外部模型。

交付包包含：可运行开场、明确启动方式、完整游玩录屏、实际阶段时长、固定角度场景与 UI 截图、补拍清单、已修复/待核实建模问题表、触发条件与事件表、B04 接入/存档版本说明和测试结果。大型实拍证据只进入现有研究/验收包路径，普通运行包不复制全部原片。

建议评审点为 P1 首次完整可玩、P2 存档稳定、P3/P4 体验与场景成型、P5 最终验收。工期在 P0 确认路线和队友接口后估算；不把上述设计时长当开发工时。
