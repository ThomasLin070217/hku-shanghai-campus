# 草坪上的守卫 · L001

2030 年的校园防御网把执行修复的管理员标记成入侵者。L001 守在核心电源前。玩家的胜利条件是亲自解除防御锁 A、B 并执行紧急断电。狮子在断电演出中安全停机，后续任务转入体育馆。

## 试玩与演示

- 直接打开 `?experience=lion-boss`，从备用超算已经上线的草坪章节开始。剧情入口 `?experience=opening` 会沿用 B6 拾取的实体 MacBook，B4 交接用第一章已有的恢复步骤接通备用电源，再前往草坪。
- WASD 移动、Shift 跑步、Space 跳跃、V 切换视角。沿标记走向狮子，看见红眼与入侵警报后退回绿色维护区，按 C 打开电脑。
- 从 Dock 打开 **Vibe Console**。输入「让狮子的运动系统暂停三秒，再恢复正常」，点「生成规则」。在右栏检查识别出的项目、目标、范围、持续时间和开销；运行「测试技能」后再「编译并部署」。第二句可以写「在我左边九米处放一个虚假的电子信标，把守卫引过去」。模型无法连接时，可以明确选择离线预设，预设照常通过测试和部署。
- 关盖后按「开始行动」，靠近当前装置。长条警示表示冲撞，扇形警示表示挥爪。按 HUD 显示的 Q 或 R 创造窗口，再在光圈内长按 F。Ghost Signal 的落点跟随视角，可在施放前拖动鼠标选点。拖动、移动、跑跳和施放都走正常游戏输入。
- [完整实机操作录像](../evidence/lawn-battle/full-demo.mp4) 使用真实本机模型，在独立浏览器存档中完成编写、测试、部署、施放、三个装置以及进入体育馆。

| 技能 | 合法目标及效果 | 持续 | 冷却 | 算力 |
| --- | --- | ---: | ---: | ---: |
| System Freeze | 短暂停止 L001 的移动和攻击 | 3 秒 | 18 秒 | 60 |
| Robot Hijack | 临时接管附近的阿树，L001 转向并追随它 | 8 秒 | 25 秒 | 50 |
| Ghost Signal | 在选定的草坪位置生成电子假目标，L001 转向追踪信标 | 6 秒 | 15 秒 | 35 |

总算力 110，最多同时装备两项。卸载可释放槽位和资源；更新已安装项目沿用原槽位。三种组合都能打开所有装置。狮子已冲出、上个效果仍在运行、技能冷却或目标越界时，HUD 会给出拒绝原因。每解开一把锁，警戒和追击强度都会上升。成功的技能只改变战况。

## 程序、接口与存档

模型请求复用 MacBook Assistant 的连接配置。项目的 LiteLLM 客户端为本地开发服务器提供同源代理。正式密钥在服务端读取。独立模型可使用 OpenAI 兼容的 Chat Completions 或已有的 Ollama 接口。详见 [端点配置](LLM-ENDPOINT.md)。

1. 玩家指令经模型解析为 JSON。白名单类型为 `SYSTEM_FREEZE`、`ROBOT_HIJACK`、`GHOST_SIGNAL`；方向为 `left` 或 `right`；射程为 4 至 16 米的整数。游戏从 `skillCatalog.ts` 补全唯一合法目标、持续时间、冷却和开销。额外字段、错误目标、越界参数、代码或不支持的意图会在验证时拒绝。
2. `VibeService.preview` 或 `preset` 返回带来源的候选方案，`test` 用实际施放规则检查正反例，`install` 重新检查当前草稿、授权、空槽和预算。HUD 读取已确认的装备槽。修改草稿会使旧方案失效。多次打开电脑不会重复扣费。
3. `createCombat` 管理巡逻、视野、警戒、追逐、招式前摇、命中、控制、恢复与停机；模型表现层沿用 L001 及原坐标。装置分别为 `defense_lock_a`、`defense_lock_b`、`ai_core_power`。场地装置采用游戏虚构的 2030 年设定。
4. 实际完成最后一次长按后，任务接入层按实体设备写入 `ai_core_power_cut`，发送同名 DOM 事件。完成关卡的链接携带设备 ID，体育馆核对该设备任务记录后显示恢复通告。该关原有数独、密码与营救逻辑继续由体育馆模块处理。
5. 存档包含实体物品、技能配置及来源、槽位、算力对应的装备、锁进度和生命。致命命中后黑屏、回到维护区、恢复十心、清除临时效果。旧草坪结局可接续到已解开两锁、待关闭新电源的进度。

本机游戏代理沿用 `GET /observe` 的只读观察（`state.boss` 包括 FSM、目标、锁、电源、装备、冷却和算力），以及 `POST /act`、`GET /commands/{id}` 的授权动作。玩家在关卡简报明确开启本机 AI 控制，再由代理取得控制 epoch。编译限维护区和已装备电脑，施放限实战合法目标。命令可去重、撤销和超时。公开静态包不开放本机控制桥。

```json
{"commandId":"compile-1","controlEpoch":123,"durationMs":30000,"boss":{"type":"compile","project":"ghost","source":"model","prompt":"在左侧制造一个电子假目标"}}
{"commandId":"cast-1","controlEpoch":123,"durationMs":800,"boss":{"type":"cast","slot":1}}
```

这里的 epoch 需替换为获取控制权时返回的值。接口中没有解除锁或写胜利状态的动作。

## 验收与团队接入

| 项目 | 验证方式 |
| --- | --- |
| 真实模型 | 本机 llama.cpp / Qwen2.5-0.5B-Instruct GGUF 输出三种类型；同一验证器、实战测试和装备流程接受了三种合法配置，拒绝跳过两把锁和越界效果。浏览器录像使用真实的自然语言生成 |
| 三种组合 | 三种两两组合均通过 FSM 测试；Chrome 中用真实按键走位、施放、长按装置进入结局 |
| 失败与恢复 | 专项实机从 2 心测试存档起步，实际触发觉醒、编译、打开 A 锁后被击倒；验证复活十心、两个装备槽、A 锁保留、临时效果和冷却清空，刷新后可继续 |
| 存档与前端 | Chrome 验证文本框的移动、空格和数字输入隔离、Ghost 准星、按键重绑、冷却和算力读档；旧规则迁移及陈旧请求由专项测试覆盖 |
| B4 与体育馆 | B6 拾取实际电脑，B4 检查点测试错误顺序拒绝和三个真实恢复操作，已装备技能随同一设备带入草坪。断电后经胜利按钮实际进入原体育馆任务 |
| 权限 | 本机 HTTP 观察、显式授权、编译、第三槽拒绝、非战斗施放拒绝、禁止直接写胜利及回收控制后旧 epoch 拒绝 |

用 `npm run check:lion-boss` 复跑状态机、编译与代理测试，使用 `npm run check:lawn-browser` 对本机开发版做完整键鼠通关。浏览器脚本使用已安装的 Chrome，可设置 `CAMPUS_URL`、`LAWN_PAIR`、`LAWN_MODEL=1`。可选 `LAWN_DEMO_VIDEO` 指定录像输出，编码需要 FFmpeg。完整键鼠回归录像长 42 秒。6–7 分钟是新玩家首次游玩的设计目标，尚待新玩家计时验证。

Harry 可通过 `registerCampusComputeSource` 按设备注入正式超算提供方；WHL 可继续替换狮子演出和动画；Frost 可订阅 `ai_core_power_cut` 接后续剧情。玩家浏览器里的存档按设备与站点保存。
