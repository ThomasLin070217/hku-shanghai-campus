# 场景编号与 Agent 接手更新

本轮保留校园外观和现有物理，在主校园静态模型上增加可追溯编号。团队只需在页面点「场景编号」，搜索或点选对象，再「复制修改任务」。复制文字包含编号、源码、作者键、范围和参考依据。

## 已交付

- 7 栋楼、14 条道路/连接平台及区域、入口、玻璃、立柱、景观等细部，共 **17,606** 个可查询条目。完整表在 `assets/scene/catalog.json`，主要编号在 `assets/scene/major-index.md`。
- 细部编号在合并网格后仍可点选；当前仍为 1,062 个渲染网格、165,608 个三角形，没有拆成 17,606 个渲染对象。
- GLB 中保存组编号及合并前部件映射，重载后校验全部 ID。完整校园约 20.75 MiB；增加的主要是可追溯元数据。
- 根目录 `AGENTS.md` 和 `docs/AI-START.md` 提供开发接手路径；离线命令 `npm run scene -- entity S001` 返回源文件和定位锚点。
- 原生本机 HTTP + WebSocket 协议升级到 `hku-campus/1.3`，新增能力发现、实体查询和受控高亮；MCP stdio 提供 10 个工具，Node CLI 和演示脚本可直接使用。

## 使用范围与维护约定

编号不等于新建通行区域：高架平台是否可走仍遵循已有碰撞系统。独立室内研究资产与未来 NPC 不纳入主校园静态索引；玩家使用 `PLAYER`，动态物品沿用既有实例 ID。

代码 Agent 可按编号修改源码；运行时 Agent 可读取、截图、高亮和执行既有动作。本轮没有提供远程任意执行代码或直接移动建筑的端点，以免模型与碰撞脱节。控制权仍需用户在页面开启，人工接管、失焦与超时规则保留。

细部 ID 来自作者键。尺寸调整不换号；同名重复部件插入/重排或重命名时必须显式保留作者键，必要时提供 ID 迁移表。索引记录的是模型世界包围范围，不是现场实测尺寸。
